# 独立外推工具与后续 Orekit 方案

## 当前入口与模型

入口包 `com.runisys.orbit.spacevisibility.domain.orbit`，普通 Java8 使用 `OrbitDefinition`、`OrbitTime`、`OrbitPropagationTool`、`OrbitState`。工具绑定一个明确原生传播实现，positionAt只查询位置，velocityAt只查询速度，stateAt查询完整状态；输出必须请求定义的原生Frame，工具不暗中换时标/坐标或选择模型。位置m、速度m/s，根数半长轴m、角度deg、偏心率无量纲。

| 原模型/绑定 | 输入时标与坐标 | 实际算法与速度口径 |
| --- | --- | --- |
| `TLE_SGP4` → `SpaceOrbitStateProvider.fromDefinition/fromTle` | TLE两行原文/内嵌UTC历元，UTC Instant；TEME输出 | 原Orekit SGP4/SDP4与alpha-5处理；速度沿原位置t-1s后t+1s中心差分 |
| `SPACE_KEPLER_J2_RK4` → `SpaceOrbitStateProvider.fromElements/fromDefinition` | `OrbitDefinition.Elements`及UTC Instant；EME2000输入、TEME输出 | 原中心引力+J2固定步长RK4（应用默认10s）；原位置差分速度，不能误称SPACE_KEPLER纯二体 |
| `TWO_BODY` → `BallisticOrbitPropagation.bind` | Elements、旧J2000 double秒，原J2000输出；步长参数须0 | 原开普勒位置迭代；新工具速度以t+1s减t-1s再×0.5，原Java位置接口没有解析速度合同 |
| `J2_SECULAR` → 同上 | 同上 | 原J2长期升交点/近地点/平均运动公式；工具速度与二体同为明确差分，不能改成Orekit数值模型 |
| `J2_NUMERICAL` → 同上 | 同上 | 原中心引力+J2固定策略RK4、最大30s分步；stateAt一次积分，原生PV速度 |
| `CARTESIAN_TWO_BODY_RK4` → `BallisticCartesianPropagation.bind` | Cartesian端点旧绝对秒及J2000位置/速度 | 拟合区间外原二体RK4、最大1s；默认旧相对锚点桥与显式绝对端点均保持，不包括拟合插值算法 |

公共工具仅组织类型边界，不依赖Spring、HTTP、数据库或桌面UI；**依赖应按具体实现区分**：弹道上述纯领域实现只需JDK；空间桥/provider仍需Orekit12/Hipparchus、初始化器用SLF4J及日志实现、外置Orekit数据。它们不需Spring/MyBatis/JUnit。完整弹道文件解析/HTTP服务的POI、MinIO等依赖不属于纯传播工具。

## 已实际执行的普通Java示例

仓库已有两份完整、可直接运行的示例，避免另造一套启动框架：

- [PlainJavaOrbitExample.java](../verification/T09/PlainJavaOrbitExample.java)：三种真实绑定（空间六根数、标准TLE、alpha-5），24位置/24速度/3完整状态与独立原provider逐位比较。
- [PlainJavaBallisticExample.java](../verification/T10/PlainJavaBallisticExample.java)：三弹道模型与笛卡尔外推，黄金72位置/24 J2状态/26拟合状态，六历史×12查询，实际断言无Spring/原兼容核心/POI/MinIO类。

在根目录运行以下既有脚本：

```powershell
$java8 = 'C:/Program Files/Eclipse Adoptium/jdk-8.0.472.8-hotspot'
./scripts/verify_orbit_tool.ps1 -JavaHome $java8 -ValidationTask T09 -EvidenceTask T29
./scripts/verify_ballistic_tool.ps1 -JavaHome $java8 -EvidenceTask T29
```

第一条用Maven仅解析 `org.orekit,org.hipparchus,org.slf4j,ch.qos.logback` 运行依赖，源码直接javac，不放backend编译类/Spring/MyBatis/JUnit到类路径；由脚本传 `orekit.data.path=backend/orekit-data` 及已有classpath的UTC资源。第二条直接javac纯领域源码，运行类路径仅生成类目录并读取有来源十六进制黄金。两个脚本都核验javac是1.8，不接受默认Java17；`EvidenceTask`只改本次证据目录，不覆盖T09/T10历史输出。

空间完整示例中的核心绑定与查询是：

```java
Instant epoch = Instant.parse("2026-07-01T10:00:00.123456789Z");
OrbitDefinition.Elements elements = new OrbitDefinition.Elements(
    OrbitDefinition.Model.SPACE_KEPLER_J2_RK4,
    7000000, 0.01, 50, 20, 30, 40, OrbitTime.utc(epoch), 10);
OrbitPropagationTool tool = SpaceOrbitStateProvider.fromDefinition(elements).tool();
OrbitState state = tool.stateAt(OrbitTime.utc(epoch.plusSeconds(3602).plusNanos(13)),
    OrbitDefinition.Frame.TEME);
```

这些声明/调用在上述完整示例实际编译运行；import及完整失败断言见源码。外部业务也可只查positionAt减少旧扫描额外传播；直接构造工具的调用者必须保证NativePropagation与定义来自同一组模型/根数，工具不会反射检查实现内参数。

## 历史、缓存和精度边界

空间桥复用同一原provider，保持位置和差分速度的调用顺序。原provider以ThreadLocal隔离线程传播状态；空间RK4保留60秒锚点和8192记录上限，普通工具不再添加缓存，不应每个采样点重建provider或跨线程共享其内部积分对象。应用 `OrbitPositionCache` 的有界缓存与任务生命周期独立，不是工具全局历元。

弹道纯传播绑定以不可变根数重新从历元计算，无历史缓存，可独立并发调用；Cartesian原端点传播亦不持有业务静态历元。旧`OrbitCalculator.utcOffsetSec`仍有Java兼容全局状态边界，HTTP固定0；独立工具显式携带偏移，查询偏移须与定义一致。不要把queryOffsetSec（相对历元查询秒差）当utcOffsetSec。

瞬时坐标、速度、原单位/时刻、非整步/反向/乱序/重复查询、跨日及实例历史分别验证。当前普通Java黄金断言逐double原始bits，同口径窗口/CSV按来源冻结基准比较；这证明已验证样本迁移行为保持，不是任意轨道/长时长物理精度上限。CSV小数位也不构成内部误差保证。历史JIT C2冷热末位约1–2e-9m及frame 2ULP特定边界仍在报告解释，不抹掉原观察。

## D01—D06 后续方案（全部暂缓）

当前保留两套数学主体；Orekit12本已用于空间模型，并不表示新Orekit弹道模型已经测得等价。必须先完成T01—T30、完整测试和已发现问题修复/复测收敛，再按台账顺序启动以下实验。这里只保留方案，不实施替换。

| 后续项 | 实验与准入 |
| --- | --- |
| D01 | 在已收敛版本建立旧实现/Orekit双跑。冻结μ/J2/地球半径/轴、根数或PV、UTC/TT区别、太阳源、速度约定、步长/节点、采样及完整误差标准；先记录逐样本和窗口/拟合差异再决定可替换项 |
| D02 | 评估KeplerianPropagator替代弹道二体；对齐时标/根数转换及输出J2000口径，状态和全部偏移窗口通过才切换 |
| D03 | Orekit数值传播重现原中心引力+J2，先对齐RK4、30s最大分步/节点、常数和参考轴；完整位置速度/可见弧/最优偏移通过才切换 |
| D04 | 评估拟合区间外1s二体传播替换，保留原始点硬约束、插值/导数估计、端点修正、起落事件容差；全轨迹及ECI/ECEF口径不劣于冻结基准 |
| D05 | 单独评估坐标、Hermite与J2长期项。坐标转换需独立核对旋转速度/含自转导数差别；长期项若不等价保留原公式由工具管理，不因模型更复杂强制切换 |
| D06 | 仅对已通过项清除被证实可删的重复实现；运行完整数值、接口、文件、并发/取消及部署矩阵，记录所有差异结论后交付 |

每项失败先定位输入/时标/轴/常数/节点或事件差异，最小修复候选实现并重跑该项受影响全集；不调整黄金/舍入掩盖、不放宽冻结容差凑通过。模型不等价或误差未收敛即保留当前原实现，注明不替换的证据。试验采用独立数据与运行目录，原版只读；每个切换有可回退的提交与实际报告，不能只凭迭代轮数验收。
