## 约束与交付范围

- 空间目标可见性规划软件是工程底座；两套原目录作为基准来源，实施不改动原目录。
- 新目录拥有独立的 `backend/` 与 `frontend/`，保留空间软件实际语言及构建环境：Java 8、Spring Boot 2.7.18、Maven、Orekit 12.0，以及 Vue 3、TypeScript、Element Plus、Vite 和现有锁文件。
- 当前阶段只抽取外推入口和现有实现，不替换弹道传播公式，不升级 Orekit，不改变积分步长、时间/坐标口径、太阳源、窗口搜索语义或拟合方法。
- 原有 HTTP 和 Java 输入输出保持兼容；弹道可见窗口载荷输入采用空间标准参数，是明确记录的变更项。输出字段及含义须逐项保留并制定载荷摘要映射，不能默默新增字段或输出不真实的锥角摘要。
- 保留空间目录筛选、下传约束、单星/共同观测、同步/异步任务、结果管理等功能，以及弹道多目标多载荷、偏移搜索、轨迹展示、102 包拟合、模拟和重定时功能。
- 弹道功能必须完成 B/S 改造：浏览器访问 Vue 前端，Spring Boot 提供全部计算与文件服务；生产运行和自动化测试不依赖 Swing 窗口、桌面文件选择器或独立示例启动程序。
- 沿用空间软件现有 api/application/domain/infrastructure 分层与标准 Maven 目录；新计算接口使用正式 Controller、请求/响应 DTO 和应用服务，算法不处理 HTTP 或桌面交互。
- 浏览器本地文件通过 HTTP 上传；计算结果通过 HTTP 下载和浏览器预览；原 csvPath、ballisticCsvPath、trajectoryCsvPath、outputDir 仍按服务端文件语义兼容，不能要求用户填写浏览器电脑的绝对路径。上传/下载作为新增辅助接口，保持既有计算接口的请求/响应契约。
- 上传、结果和临时文件属于运行期存储，目录通过 Spring Boot 配置管理，与 Java 源码、resources 和前端源码分开；部署包支持无桌面环境运行。
- 空间生产下传仍使用现有站点/光照/保护规则，不因增加 GROUND 载荷输入而修改其语义。

## 状态与顺序规则

状态使用：`未开始`、`进行中`、`待测试`、`待修复`、`已完成`、`暂缓`。用户已确认主阶段实施，后续底座统一仍按其进入条件执行。

1. 用户确认后从 T01 开始，严格按 T01 至 T30 顺序执行；同一时刻只推进当前事项。
2. 开始一条事项时更新为“进行中”，记录开始时间；实现完成后更新为“待测试”。
3. 执行该条规定的测试/核验及受影响的回归，保存命令、环境、结果、报告和必要原版对照数据。
4. 有失败或验收差异则更新为“待修复”，记录根因、修复轮次与复测；继续处理当前条，不能跳到下一条。
5. 验收通过，并完成中文注释、代码规范和提交内容检查后，才更新为“已完成”；记录完成时间、实际结果、证据路径与提交标识，完成代码/测试/文档及台账的对应提交后，再执行下一条。
6. 文档、版本冻结和目录准备事项按其核验要求验收，不编造不必要的自动化测试。环境阻塞或无法运行必需测试时记录原因，不能标为“已完成”。
7. 后续修改导致已完成事项回归失败时，记录关联事项并重新复测；需要返工的事项恢复为“待修复”，问题收敛后再继续。
8. D01 至 D06 当前均“暂缓”；T01 至 T30 完成且完整回归/修复已收敛后，按后续顺序进入外推底座统一。执行过几轮本身不构成验收通过，不强行替换不等价模型。

## B/S 改造与 Web 工程组织

弹道可见窗口、102 包拟合、模拟和重定时全部纳入浏览器应用。生产启动只使用空间主工程的 Spring Boot 服务入口，前端由 Vue 实现；原 Swing 页面与独立 API 示例启动器不作为新项目的生产入口。算法与兼容 Java 调用保持可独立测试，不能创建桌面窗口或依赖桌面事件。

后端沿用空间软件现有分层，新增内容放入对应层，旧包名如需兼容只保留必要适配入口：

```text
backend/
  pom.xml
  src/main/java/com/runisys/orbit/spacevisibility/
    api/                    Controller、请求与响应 DTO
    application/            计算编排与 Web 文件服务
    domain/                 空间/弹道算法及公共外推工具
    infrastructure/         数据库、文件存储与配置适配
  src/main/resources/       application 配置、数据库迁移、必要资源
  src/test/java/            单元、算法回归和 HTTP 集成测试
  storage/                  可配置的 uploads、results、temp 运行期目录
frontend/
  src/api/                  后端接口调用
  src/types/                接口与页面类型
  src/components/           共用载荷编辑、结果展示组件
  src/views/                空间及弹道各功能页面
```

兼容与文件流转规则：
- 原 /api/orbit/visibility/search、/api/trajectory/fit/package102、/simulate、/retime 仍保留原 HTTP 方法、计算请求/响应、错误语义和时间/文件格式。弹道载荷输入变更按原台账单独记录。
- 新增上传、下载和必要的预览辅助接口采用标准 Spring MVC HTTP 处理。上传后的服务端文件引用适配既有 csvPath/ballisticCsvPath/trajectoryCsvPath 字段；结果文件与下载引用的对应关系由服务端管理，不把旧计算响应强制替换成新的统一响应包装。
- 原路径字段表示服务端可访问的文件/原支持的远程地址；浏览器本机文件须上传后再计算。服务端 outputDir 的兼容规则保持，浏览器正常操作的输出位置由部署配置管理。
- 同一次生成/重定时的结果可直接成为后续窗口计算的输入，浏览器无需下载后重新填写服务器文件路径。
- 上传、结果和临时文件不写入 src/main/java、src/main/resources 或前端源码；管理目录、清理策略和下载规则有明确配置和验证。
- B/S 验收通过浏览器实际执行上传→计算/拟合/模拟/重定时→轨迹/弧段展示→结果下载→结果复用；后端在无桌面环境中运行。不能只以旧 Java 算法测试通过认定 Web 改造完成。
