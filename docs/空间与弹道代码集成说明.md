# 空间与弹道代码集成说明

## 一、完整工程与已有空间系统

完整工程以SpaceTargetVisibleApplication启动，API、应用流程、领域计算和基础设施均按空间、弹道与公共职责组织。直接使用本工程时，按[源码包说明](../源码包说明.md)导入backend/pom.xml并构建即可。

已有空间目标功能的系统，可按[弹道增量代码集成说明](弹道增量代码集成说明.md)加入弹道闭包，沿用其现有空间业务。若同时采用本版空间包布局，则按下文更新空间源码及Java引用，逐项合并宿主自己的改动。

## 二、目录与集成边界

路径均相对于backend/src/main/java/com/runisys/orbit/spacevisibility。

| 目录 | 内容 | 接入关注点 |
| --- | --- | --- |
| api/space | 3个空间控制器 | 目录、规划、任务及结果记录HTTP入口 |
| application/space | 18个空间编排类及1个契约文件 | 目录读取、参数转换、并发任务和结果保存 |
| domain/space | 29个空间模型与算法类 | visibility、downlink、geometry、illumination、orbit |
| infrastructure/space/persistence | 10个数据库适配类 | 实体、Mapper、演示数据与分页配置 |
| api/ballistic、application/ballistic、domain/ballistic、infrastructure/ballistic/files | 弹道窗口、拟合、模拟、重定时与文件服务 | 最小增量清单见弹道分册 |
| domain/geometry、orbit、payload、time、window | 公共领域能力 | 共享向量/数学、轨道查询、标准载荷、时间和区间实现 |
| api/common、infrastructure/common/web | 公共Web边界及容器支撑 | CORS、全局异常和Tomcat配置 |

公共包仅维护一份实现。两侧专有传播、太阳和采样计算分别保留原口径；包整理不改变数值模型或强制改用同一传播实现。

## 三、空间规划内部调用入口

| 用途 | 当前入口 |
| --- | --- |
| 空间规划总入口 | application.space.PlanningFacadeService |
| 单星—目标配对及计算编排 | application.space.VisibilityPlanningService |
| 同目标多星窗口与时长约束 | domain.space.visibility.VisibilityConstraintPlanner |
| 下传链路编排 | application.space.DownlinkPlanningService |
| 下传领域算法 | domain.space.downlink.DownlinkPlanner |
| 异步任务、结果记录 | application.space.PlanningTaskService、VisibilityTaskResultService |
| 空间用例输入输出 | application.space.contract.SpacePlanningModels |

Controller直接绑定SpacePlanningModels中的契约类型；应用服务使用同一份定义。字段、默认值、Bean访问器及JsonFormat/JsonIgnore规则保持。空间领域模型不引用该契约、HTTP或持久化实体。

## 四、从前一版更新Java引用

Java包归属发生变化，HTTP路径、JSON字段和文件格式保持。宿主需重新编译，不依赖前版FQN的二进制兼容。

| 前一版位置 | 本版位置 |

| application中的空间流程、任务、目录和结果服务 | application.space |
| application中的观测模型、采样/缓存、VisibilityConstraintPlanner | domain.space.visibility |
| application.DownlinkPair、DownlinkPairResult | domain.space.downlink |

| domain.payload中的SolarGeometry、IlluminationConstraint/State | domain.space.illumination |
| domain.geometry中的地面站几何及TemeEarthFixedFrames | domain.space.geometry |

| domain.orbit中的BallisticOrbitPropagation、BallisticCartesianPropagation | domain.ballistic.propagation |

## 五、Spring、数据库与文件配置

本工程启动类扫描com.runisys.orbit.spacevisibility。宿主使用其他根包时，按所需能力扫描api.space、application.space、infrastructure.space.persistence，弹道扫描范围见分册；共用CORS/异常及容器支撑按宿主实际配置合并，避免重复Bean。

Mapper扫描须更新为：

```java
@MapperScan("com.runisys.orbit.spacevisibility.infrastructure.space.persistence.mapper")
```

数据库配置、SQL表与Flyway迁移目录保持。Flyway的java/db/migration和resources/db/migration沿用框架发现约定。弹道文件根、大小、TTL与multipart单Bean约束见弹道分册。

如果宿主已有统一响应包装、鉴权或异常Advice，按35项实际HTTP合同定向接入。窗口流式JSON、健康文本、文件下载与既有业务对象保持各自返回方式，文件存储适配器引用应用文件契约。

## 六、集成后的验证顺序

1. 编译并确认空间24项、弹道及辅助11项操作唯一注册。
2. 验证空间目录、载荷、下传、同步/异步观测、取消及结果记录；再验证弹道文件与四类计算。
3. 同条件比较空间弧段、多星组合、下传结果，及弹道全部偏移、最佳偏移和CSV原字节。
4. 运行宿主自己的数据库、网关和部署回归。本工程A18已验证完整测试、严格数值与原空间4类复用的弹道增量闭包；宿主定制版本需按其实际代码验证。

HTTP字段使用[完整接口文档](接口文档.md)和[OpenAPI](openapi/openapi.json)，Java阅读顺序见[后端代码说明](../backend/代码说明.md)。
