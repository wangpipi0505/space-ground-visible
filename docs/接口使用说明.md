# 实际 HTTP 接口与可执行示例

本说明依据正式 `api` Controller、原 `com.tx.alg` DTO、应用服务和前端 API 编写，辅助接口均已实现。T03 文档是冻结设计快照，保留作历史对照。服务根示例为 `http://127.0.0.1:18131`；Vue 使用同源 `/api`，需要完整独立根时按[前端说明](前端载荷配置说明.md)配置。成功体保持原数组/对象或手写 JSON，不统一增加 wrapper。

## 路由与 DTO 对照

空间前缀 `/api/v1/space`，来源 `backend/src/main/java/com/runisys/orbit/spacevisibility/api/`。以下24条均已列入T03冻结空间路由；其中GET/PUT `payload-profiles` 在冻结原空间Controller第120/129行就已存在，T20/T21复用既有空间入口并将标准载荷编辑/校验扩展到弹道，不是本轮新增空间路由。原空间接口与原字段兼容保持：

| 方法与相对路径 | 输入/输出和调用用途 |
| --- | --- |
| GET `/health` | `{status:"UP"}`，轻量探针不访问库/计算资源 |
| GET `/satellites` | 原 `SatelliteEntity[]`，含数据库轨道/载荷；按主键排序 |
| GET `/satellites/page` | `pageNumber=1,pageSize=50,keyword?` → `PageResponse<SatelliteSummaryResponse>` |
| GET `/satellites/options` | 轻量 `SatelliteOptionResponse[]`；不把目录摘要当作弹道根数 |
| GET、PUT `/satellites/{satelliteId}/payload` | 旧 `SpacePayloadConfigurationRequest/Response` 对空兼容入口；公里与米字段不能混发 |
| GET `/satellites/{satelliteId}/payload-profiles` | `PayloadProfilesResponse{activePayloadType,profiles}` |
| PUT `/satellites/{satelliteId}/payload-profiles` | `PayloadProfileRequest` 十业务字段；保存指定类并启用，保留另一类 |
| GET `/stations` | 原 `StationEntity[]`，站点基础信息 |
| GET `/defaults` | 原保护/断链/时效/历元筛选默认值 |
| GET `/targets/belong-options` | 实际目录 `BelongOptionResponse[]`，不在客户端硬编码国籍集合 |
| POST `/targets/query` | `TargetQueryRequest` → `TargetQueryResponse`，分页目标及全筛选 `targetIds` |
| POST `/downlink/plan` | `DownlinkPlanRequest` → 原独立链路/连续覆盖/失败链路结果 |
| POST `/downlink/validate-window` | 同一请求 → `WindowValidationResponse{satisfied,plan}` |
| POST `/visibility/plan` | `VisibilityPlanRequest` → `VisibilityPlanResponse`，同步等待 |
| POST `/visibility/tasks` | 同一请求 → `{taskId:string}`，受理后异步执行 |
| GET `/visibility/tasks/{taskId}` | `PlanningTaskStatusResponse`，进度及真实状态 |
| GET `/visibility/tasks/{taskId}/result` | 成功后原 `VisibilityPlanResponse`；未知404，未成功409 |
| DELETE `/visibility/tasks/{taskId}` | 当前真实状态；受理取消后仍可能 RUNNING |
| GET `/visibility/task-results` | `pageNumber=1,pageSize=20,status?,keyword?` → 记录分页 |
| GET、PUT、DELETE `/visibility/task-results/{id}` | 明细读取、`{remark:string|null}`更新、删除；未知404，删除成功200空体 |
| PUT `/visibility/task-results/{id}/selection` | `planningWindow/mergedTimeRange/selections/remark`；selections必须非空数组，保存原文与回执 |

弹道正式 Controller 位于 `api/ballistic`，保留以下 6 条原计算路由。`BallisticVisibilityController` 继承旧窗口健康方法，`BallisticFitController` 自身声明原轨迹健康入口；`com.tx.alg.api` 原类供 Java 兼容，未纳入 Spring 扫描，不另挂重复端点。

| 方法与完整路径 | 实际 DTO 与输出 |
| --- | --- |
| GET `/api/orbit/health` | 文本 `OK` |
| POST `/api/orbit/visibility/search` | 原 `VisibilityRequest` → 原 `LaunchSearchResultV2.writeJsonTo` 流式 JSON |
| GET `/api/trajectory/health` | 文本 `OK` |
| POST `/api/trajectory/fit/package102` | 原 `TargetTrajectoryFitter.FitRequest` → `FitRunResult` |
| POST `/api/trajectory/simulate` | 原 `SimulationRequest` → 同一 `FitRunResult` |
| POST `/api/trajectory/retime` | 原 `RetimeTrajectoryRequest` → 同一 `FitRunResult` |

新增辅助接口共 5 条：

| 方法与完整路径 | 实际输入/输出 |
| --- | --- |
| POST `/api/v1/ballistic/payloads/preview` | `VisibilityRequest.PayloadDef` 的payloadId/payloadName和十标准字段 → 原值回显12字段；不保存配置 |
| POST `/api/v1/ballistic/files` | multipart `file`及可选`purpose` → HTTP201 `FileReference` |
| POST `/api/v1/ballistic/files/register-result` | `RegisterResultRequest{csvPath,taskName?,targetId?}` → HTTP201 `FileReference`，重复有效登记复用ID |
| GET `/api/v1/ballistic/files/{fileId}/preview` | `page=1,limit=50`（默认上限500） → `Preview{fileId,header,rows,totalRows,page,limit,metadata}` |

## 主要请求及兼容字段

完整字段/默认表达式、实际源码行号与来源指纹见[本轮清单](../verification/T29/api-inventory.json)，不是重新定义的DTO。前端结构分别见 `frontend/src/api/types.ts`、`ballisticWindowTypes.ts`、`ballisticFitTypes.ts`、`utils/ballisticSimulation.ts`，HTTP函数位于同目录对应API文件。

| 请求 | 实际重要字段与语义 |
| --- | --- |
| `TargetQueryRequest` | `targetIds,belongs,minWeight,maxWeight,epochStartTime,epochEndTime,minTleEpochCode,maxApproximationDays,planningStartTime,planningEndTime,excludeNameRegex,pageNumber,pageSize`；页面默认1/50，最大200；目录筛选顺序/星历风险由原服务处理 |
| `DownlinkPlanRequest` | `startTime,endTime,coarseStepSec=60,fineStepSec=1,satelliteIds,preGuardSec,postGuardSec,allowedGapSec,satelliteIllumination,stations[{stationId,minElevationDeg,maxElevationDeg}],links[{satelliteId,stationId}]`；保护/间隔秒，仰角度，缺省取站点及服务defaults，GROUND观测载荷不替换该下传逻辑 |
| `VisibilityPlanRequest` | `observerSatelliteIds,targetIds`及上述目标筛选；`startTime,endTime,coarseStepSec=60,fineStepSec=1,illuminationConstraint{mode,observerStates,targetStates},observationConstraints[{satelliteIds,minDurationSec}],winToolReport`；目标空集合按原筛选全量，每个组合求共视而不是时长简单相加 |
| `VisibilityRequest` | `ballistics`非空优先多目标，否则旧`ballisticCsvPath/baseLaunchUtc`单目标；扫描`startOffsetSec=-500,stepSizeSec=10,numCalculations=101,targetSampleStepSec=1,trajectoryPointOutput=1,orbitModel=J2_NUMERICAL`；偏移步长/次数为正，采样≤0用原自动步长 |
| `BallisticDef` | `csvPath,targetId,targetName,baseLaunchUTC/baseLaunchUtc/baselaunchUTC`；按此顺序取非空发射UTC，否则每个文件自身历元，不用全局历元覆盖多目标 |
| `SatelliteDef` | `satelliteId,name,semiMajorAxisM,eccentricity,inclinationDeg,raanDeg,argumentOfPerigeeDeg,meanAnomalyDeg,epochUtc,payloads`；半长轴米/角度度/平近点角；显式星默认7530612/.00085/64.8/120/270/0，空列表为SAT-A/B且平近点角30/0；缺epochUtc取原2026/07/01 10:00:00，无epochSec HTTP字段 |
| 旧弹道载荷入口 | 顶层`payloadType,maxDetectRangeKm,sunExclusionAngleDeg,sensorFovDeg`及内嵌`payloadId,payloadName,payloadType,maxDetectRangeKm,sunExclusionAngleDeg`保留；空内嵌载荷回退顶层，旧中文四类继续原圆锥/环形分支。不要把Java `legacySimpleCone(140)`伪装成HTTP内嵌PayloadDef字段 |
| `FitRequest` | `package102,taskName,taskStartTime,taskEndTime,interpolationStepSec=1,outputDir`；原`tack3d`拼写与`track3d_time_code`、`coordinateInfo/coordinate/coords`、`targetInfo/target`别名保留；编码位置0.1m/速度0.0001m/s/加速度0.01m/s²；步长最小.001s，任务输出区间与物理起落时刻分开 |
| `SimulationRequest` | 原35字段保留；任务/目标、字面UTC起落及输出区间、`launchPointX/Y/Z,launchPointCoordFrame,launchPointUnit`与impact对应字段、`outputPointDurationSec=1,phaseEvents,outputDir`构成端点约束路径；旧经纬/速度/积分/推力等字段仍可反序列化，但当前端点路径不以它们替代端点求解。`impactTime`保留旧别名 |
| `PhaseEvent` | `phaseType,eventType,startTime,endTime,eventTime,dynamics,directionMode,accelerationMs2,deltaVms,liftDragRatio,dragCdAreaOverMass`按原事件/动力学解析；加速度m/s²，deltaV m/s，不凭名称猜未使用分支的模型 |
| `RetimeTrajectoryRequest` | `taskName="retimeTrajectory",targetId="RETIMED-TGT",trajectoryCsvPath,launchTimeUtc,outputDir="."`；真实模拟/拟合CSV列名须满足原解析要求，旧窗口标准CSV不是同一重定时输入格式 |

`FitRunResult` 只有 `taskName,targetCount,files`；每文件 `targetId,model,csvPath,pointCount,warnings`。网页省略 outputDir 使用管理结果独占目录，原DTO默认`.`只描述直接旧Java/显式旧请求语义；明确发送outputDir（含`.`）按旧服务端目录兼容。原CSV、摘要、数值顺序由原实现输出。

## 文件流转与取消/错误

浏览器先 POST 文件，**确认201** 后才能使用返回 `fileId` 预览/下载及 `serverPath` 计算。文件服务器与浏览器不是同一机器，`File.name`、fakepath、本机绝对路径不构成服务端引用。窗口单目标赋 `ballisticCsvPath`、多目标赋 `ballistics[].csvPath`，重定时赋 `trajectoryCsvPath`。原 HTTP/HTTPS、MinIO 或服务端路径计算兼容仍保留；浏览器直接远程引用计算不等于已纳入管理下载。

计算成功后取**实际响应**的 `files[].csvPath` 登记结果，201取得ID，再预览/下载，或将此serverPath回用于窗口/重定时。只能登记结果管理根中的现存文件，不允许任意系统路径、越界符号链接或过期ID。上传/下载/计算输入租约防清理，结束/中断释放；TTL到期且无租约可删除字节与登记，之后404须撤销旧引用或重新登记/上传。失败独占输出回滚，显式旧目录不当作可随意清理的独占目录。

异步任务状态 `PENDING → RUNNING → SUCCEEDED/FAILED/CANCELLED`。DELETE 200 可能返回RUNNING，仅受理协作取消，前端继续轮询；确认CANCELLED后结果GET是409，历史记录真实为CANCELLED。若成功先完成，再取消保留成功结果。GET result409对PENDING/RUNNING/FAILED/CANCELLED均成立，不能一见409就称“取消成功”。内存任务受原TTL约束，持久化记录独立；取消内存任务不是删除记录。

错误保持当前实际协议：

- 空间业务非法参数400 `{code:"INVALID_ARGUMENT",error}`；其他异常500 `{code:"INTERNAL_ERROR",error:"服务处理失败",requestId}`。例如非法Instant反序列化在旧空间handler走500，勿统一改写成400；未知任务/记录404可为空体。
- 弹道三轨迹计算参数400、其它计算异常500 `{error:describeFailure}`；窗口保持原手写error JSON及转义范围。绑定/流式传输故障按实际MVC边界处理，不保证每个错误具有同一包体。
- 新文件辅助400/404/413/500使用自身`{code,error,requestId?}`；标准payload preview非法400 `INVALID_ARGUMENT`。大文件超限413，不把失败响应保存成CSV。

空间请求卫星/目标ID是Long对应JSON数字，站点ID字符串；观测结果里的ID字符串，持久化记录主键十进制字符串而路径绑定Long。弹道身份都是字符串，别统一强转。空间Instant毫秒UTC带Z；记录LocalDateTime按原无Z格式，JSON原文字段 `requestJson/resultJson/skippedPairsJson/selectionJson`仍是字符串。

## 直接执行已验证示例

启动全新独立 demo/H2（见README），从根运行，仅需Python标准库：

```powershell
python docs/examples/http_flow.py --base-url http://127.0.0.1:8080
```

示例会保存隔离运行请求/响应，完成目录/筛选/两类载荷接口、下传/覆盖、同步与异步一致、取消与409、记录备注/选择/删除、真实上传201→预览→下载→旧/标准窗口、102拟合、模拟结果登记→重定时及未知404。来源为 `test-data/baseline/ballistic/conditions.json` 与 `test-data/reference/ballistic/trajectory-0.1s-standard.csv`，不是伪造请求。脚本对结果CSV逐字节黄金比较；旧Java简单锥六案例不当作HTTP圆锥黄金。脚本会改变demo载荷、创建计算结果及维护自身生成记录，请用独立运行根。

HTTP可独立调用，例：

```powershell
$api = 'http://127.0.0.1:8080'
curl.exe --fail-with-body "$api/api/v1/space/health"
curl.exe --fail-with-body -F 'file=@test-data/reference/ballistic/trajectory-0.1s-standard.csv' "$api/api/v1/ballistic/files"
```

上传返回的fileId与serverPath随运行变化，后续完整调用已在脚本中真实传递，不提供假ID/假本机路径。本轮实际执行命令、状态、CSV校验及修正过的示例黄金口径见[验证报告](../verification/T29/验证报告.md)。
