# 后端代码说明

## 一、工程入口和阅读顺序

本目录为Java8、Spring Boot2.7.18、Orekit12.0的Maven工程。入口是[SpaceTargetVisibleApplication.java](src/main/java/com/runisys/orbit/spacevisibility/SpaceTargetVisibleApplication.java)。建议从对应业务的Controller进入，再读应用服务、领域计算与基础设施。

```text
backend/
├─ pom.xml                       依赖、Java版本及打包配置
├─ maven-repository/             随包Maven依赖及构建插件
├─ maven-settings.xml            离线构建设置
├─ orekit-data/                  星历、地球定向与闰秒数据
├─ db/                          MySQL、达梦建表脚本
└─ src/main/
   ├─ java/com/runisys/orbit/spacevisibility/
   │  ├─ SpaceTargetVisibleApplication.java
   │  ├─ api/                   HTTP边界
   │  ├─ application/           空间、弹道用例编排及输入输出契约
   │  ├─ domain/                业务模型、规则、算法及共用领域能力
   │  └─ infrastructure/        文件、数据库与Web运行支撑
   ├─ java/db/migration/         Flyway Java迁移
   └─ resources/                应用配置、SQL迁移、类路径闰秒资源
```

domain表达核心业务，并非所有工具类的集合。窗口、轨道、载荷的模型和数学规则属于领域；文件下载、数据库访问、HTTP响应处理分别由其所在层负责。

## 二、接口边界：api

```text
api/
├─ space/       空间目录、规划任务与结果记录控制器
├─ ballistic/   弹道窗口、拟合、模拟、重定时、文件和载荷控制器
└─ common/      两侧共用的CORS与全局异常处理
```

| 业务 | 主要入口 |
| --- | --- |
| 空间目录、载荷、下传和同步观测规划 | space/SpaceVisibilityController |
| 空间异步任务、进度和取消 | space/PlanningTaskController |
| 空间结果记录、备注与选窗 | space/VisibilityTaskResultController |
| 弹道可视窗口 | ballistic/BallisticVisibilityController |
| 102拟合、系统模拟、重定时 | ballistic/BallisticFitController、BallisticSimulationController、BallisticRetimeController |
| 弹道上传、登记、预览、下载与载荷校验 | ballistic/BallisticFileController、BallisticPayloadController |

空间的输入输出集中在application.space.contract.SpacePlanningModels；HTTP直接绑定这些用例契约，字段与Jackson规则只维护一份。弹道窗口VisibilityRequest实现应用输入视图；拟合请求BallisticTrajectoryRequests继承领域输入；文件辅助契约位于application.ballistic.contract.BallisticFileModels。

具体HTTP字段见[完整接口文档](../docs/接口文档.md)、[窗口分册](../docs/ORBIT_VISIBILITY_API.md)和[拟合分册](../docs/TARGET_TRAJECTORY_FIT_API.md)。

## 三、用例编排：application

```text
application/
├─ space/
│  ├─ contract/                 空间用例输入、输出和序列化约定
│  ├─ PlanningFacadeService     空间规划总入口
│  ├─ VisibilityPlanningService 观测配对、并发执行与结果收集
│  ├─ DownlinkPlanningService   下传链路编排
│  ├─ PlanningTaskService       异步任务生命周期
│  ├─ VisibilityTaskResultService 结果记录、备注与选窗保存
│  ├─ ReferenceDataService      空间基础目录查询
│  └─ 其余服务与模型             参数转换、筛选、输出整理及跳过原因
└─ ballistic/
   ├─ contract/                 文件上传、登记和预览契约
   ├─ BallisticVisibilityService 窗口输入转换、文件加载与搜索编排
   ├─ BallisticFitService        102拟合输出工作区与登记
   ├─ BallisticSimulationService 系统模拟工作区与登记
   ├─ BallisticRetimeService     重定时工作区与登记
   ├─ BallisticTrajectoryService 本地/远程弹道读取作用域
   ├─ BallisticFileService       分页原文本预览编排
   └─ BallisticVisibilityInput   窗口应用输入视图
```

应用服务负责组织业务过程。DownlinkCoverageWindowMerger、DownlinkWindowValidator按规划契约汇总或核验输出；OrbitStateProviderFactory、PayloadConstraintFactory把目录配置转换为领域输入。它们与空间业务一起位于application.space。

## 四、核心模型与计算：domain

```text
domain/
├─ space/
│  ├─ visibility/  观测星、目标、弧段、统计、采样及多星组合规则
│  ├─ downlink/    星地链路、下传窗口和照明要求
│  ├─ geometry/    地面站几何及TEME/地固坐标口径
│  ├─ illumination/ 空间光照状态、约束及太阳几何
│  └─ orbit/       空间TLE/六根数传播及其既有Orekit上下文支撑
├─ ballistic/
│  ├─ visibility/  弹道可视窗口、发射偏移搜索及JSON写出
│  ├─ trajectory/  102拟合、系统模拟与重定时
│  └─ propagation/ 弹道卫星与笛卡尔外推实现
├─ geometry/       共用向量、数学与既有J2000转换口径
├─ orbit/          共用轨道定义、时间标签、状态、查询契约与工具
├─ payload/        共用标准载荷、约束模型与数学判据
├─ time/           既有J2000时间转换
└─ window/         通用扫描、状态区间、区间交并与归并
```

### 4.1 空间目标

VisibilityObserver、VisibilityTarget、VisibilityArc、VisibilityPairResult等定义观测业务模型；ObservationSampleEvaluator负责单时刻采样判定，OrbitPositionCache只缓存本次计算内的位置。VisibilityConstraintPlanner与CombinationWindowCalculator执行同目标多星共同窗口及累计时长规则。下传入口为space.downlink.DownlinkPlanner。

空间应用服务调用上述模型和规则，并复用domain.window.TimeWindowScanner等通用能力。空间的完整规划同时包含应用编排与领域计算，不集中在window目录。

space.orbit的TleOrbitStateProvider、KeplerOrbitStateProvider与SpaceOrbitStateProvider保持现有传播和缓存策略；SpaceTimeFrames负责对应时标坐标口径。OrekitDataInitializer作为该传播实现的既有上下文支撑同包维护；此次整理保留数据初始化时机和源选择。

### 4.2 弹道目标

[visibility/OrbitCalculator.java](src/main/java/com/runisys/orbit/spacevisibility/domain/ballistic/visibility/OrbitCalculator.java)保留窗口计算入口与结果类型。同包六个辅助实现分别承担发射搜索、轨迹读取、采样、几何判定、弧段处理和结果写出。

[trajectory/TargetTrajectoryFitter.java](src/main/java/com/runisys/orbit/spacevisibility/domain/ballistic/trajectory/TargetTrajectoryFitter.java)提供fitPackage102ToCsv、simulateToCsv、retimeTrajectoryToCsv。领域输入为FitInput、SimulationInput、RetimeInput；观测、事件、拟合点和结果共用既有定义。propagation中的两类实现保持原数值公式和步长。

### 4.3 公共能力

标准载荷统一使用PayloadConstraint、PayloadConstraintMath和StandardPayloads；向量和基础数学使用Vector3、GeometryMath；区间交并使用WindowIntervals；外推查询使用OrbitDefinition、OrbitTime、OrbitState和OrbitPropagationTool。

公共代码只保留一份，两侧按明确的时间和坐标口径调用。空间与弹道的专有太阳、采样和传播实现各自归业务包，本轮不借迁包替换物理模型。

## 五、技术适配：infrastructure

- space.persistence.entity/mapper：空间数据库实体、Mapper和分页配置；DemoDataInitializer初始化演示目录。
- ballistic.files：BallisticFileConfiguration配置限额和目录；BallisticFileStorage管理登记、租约、结果和临时工作区；TrajectoryFileResolver处理本地、HTTP/HTTPS和MinIO地址。
- common.web：两侧共用的Tomcat协议及运行支撑。

上传、登记和下载由BallisticFileController调用文件存储适配器，分页原文本预览由BallisticFileService编排。存储适配器直接使用应用层文件契约保存元数据，不依赖Controller或HTTP请求类。数据库迁移仍由标准Flyway目录发现，SQL表和迁移顺序保持。
