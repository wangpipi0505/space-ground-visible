## 实现与原契约

正式 `api.ballistic.BallisticRetimeController` 注册 `POST /api/trajectory/retime`，唯一 `application.ballistic.BallisticRetimeService` 编排输入租约、原重定时和结果登记。旧 `com.tx.alg.api.TargetTrajectoryFitController` 保持无参构造、三计算方法、注解与 ErrorResponse，仍未被主程序扫描；健康仅由既有正式入口提供，真实 HTTP 为纯文本 `OK`。没有继承旧控制器或重复注册三条路由。

成功直接返回原 FitRunResult：taskName、targetCount、files 以及每文件 targetId/model/csvPath/pointCount/warnings，没有包装或 fileId。计算 IllegalArgumentException 返回 400，其余计算/存储异常返回 500，错误仍只含 `error=describeFailure`，异常类型前缀保留。绑定采用既有 ObjectMapper，Controller 先以 JsonNode 记录 outputDir 是否存在，再绑定原五字段 DTO；绑定异常沿用既有 MVC 规则。本项目的全局 Exception 兜底实际返回 500 INTERNAL_ERROR 包体，不将其误宣称为计算 400。

RetimeTrajectoryRequest 的 taskName/targetId/trajectoryCsvPath/launchTimeUtc/outputDir 均未改变，Java outputDir 默认仍为 `"."`。服务明确复制五字段，只修改缺省目录执行副本，不改变调用者对象；带两侧空白的输入路径仍按原 trim 处理。原路径、目标标识、警告和错误文本保持。

原数值主体仅抽取两段前置代码，数值/CSV 主体未改：`validateRetimeRequest` 执行原 null → source 非空 → launch 非空 → Paths.get(source.trim) → source 存在；`prepareRetimeOutputDirectory` 执行原 Paths.get(outputDir) / Files.createDirectories。旧入口仍按这两段、UTF-8 读文件、列/行/原时刻、解析新时刻、输出的顺序执行。应用服务先完成源存在性校验，才分配工作区，并在获取受管理输入租约前执行原目录创建，避免新增管理限额异常抢占原输出路径错误。算法调用再次复用同一前置函数，不复制阈值、列处理或时刻解析主体。

组合非法输入逐项对照旧 Java 入口；显式冻结模式另以独立子优先 ClassLoader 对照原 classes。缺源+非法目录、空源+空发射时刻、非法 source+空 launch、无 YYYY / ECEF_X(m)+非法新时刻、空文件/错误列+普通文件输出目录及含 NUL 输出目录的错误类、状态、describeFailure 全一致。没有提前解析新时刻，错误列仍先于新时刻非法。原重定时只读取本地 CSV；HTTP/MinIO/Excel 是 visibility 解析能力，本项没有把它接入重定时或替换原列处理。

## 文件生命周期及新增管理约束

省略 Web outputDir 时复用 T15 `BallisticFileStorage.ResultWorkspace`，在配置 results 下建立独占 `fit-*` 目录。生成的实际 CSV 自动登记，全部登记后 complete，再返回原响应；未重新实现所有权、ID、TTL 或清理器。辅助登记前直接读取持久 metadata 确认已自动登记，两次 register-result 得到同一 ID，完整下载与实际 CSV 字节一致，预览表头及三行所有单元格一致。已上传 serverPath、已模拟自动登记的 csvPath 和未登记旧本地路径均实际完成重定时。

租约复用 storage.acquirePath，覆盖输入读取前、原重定时、输出登记完成；有租约的已上传及已登记结果，在读取前与输出登记时强制触发过期清理，实体均仍存在。计算退出释放输入租约后再次清理可删除已过期输入。该探针只暂停测试存储调用以形成确定交错，执行真实 readAllLines、原数值写出、真实存储登记和清理，没有修改产品锁或 TTL。

显式管理内/外目录依原路径写入；管理内结果自动登记，外目录计算成功但辅助登记越界返回 400。独立 headless 子 JVM 在系统临时 cwd 启动正式 Boot，真实 HTTP 分别验证显式 `"."`、空白和 null，输出均在该临时 cwd，辅助登记均因管理范围拒绝，没有运行输出写入源码。

原第二行 ECEF 非数字会在 writer 已产生部分 CSV 后失败：缺省独占目录和元数据全部回滚；显式目录的既有 keep.csv 以及原部分 CSV 保留，符合原行为。结果登记超限也只回滚本请求，另外已登记结果和其下载租约仍可用。

管理文件仍受 T13/T15 的输入字节限额等约束：上传后实体被外部扩展超过 maxBytes，acquirePath 返回原 ManagedFileException；正式计算接口实际为 500 `{error:"ManagedFileException: 文件超过配置字节上限"}`，没有转成辅助接口 413/code 包体。含 NUL/普通文件输出目录仍先于该新增限额异常，与旧入口异常一致。未登记旧本地路径不施加输入管理限额；其缺省输出登记仍受结果限额。管理限额可能在 CSV 列解析前拒绝被扩大的受管理输入，这是既有存储约束，未将它宣称为旧 Java 路径行为。

实际结果 csvPath 还被提交给正式 visibility/search；卫星 epochUtc 明确为新发射同日，HTTP 200、allResults 恰有一条偏移结果。此测试只证明文件再输入和接口成功，不断言可见弧段或物理可见性，未因空窗口改变几何/采样模型。
