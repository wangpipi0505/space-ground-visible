## 二、实际代码检查

1. 产品源中旧 `com.tx.alg` 十二个文件已移除，两个兼容控制器没有迁入产品。`domain.ballistic` 包含 `OrbitCalculator`、六个同包窗口辅助类及 `TargetTrajectoryFitter`，文件地址下载器归入 `infrastructure.files`。六个辅助类逐文件与基线比对，除包及导入外文本一致。
2. `OrbitCalculator` 删除了四个不带加载器的多目标便利重载和两个 String 地址解析重载；领域保留同一显式 `BallisticCsvLoader` 端口及 Path/InputStream/Reader 解析。原地址解析组合原样转入基础设施，正式应用仍通过文件服务维护租约、临时文件和逻辑源地址。没有新增静态全局下载器注入。
3. 拟合器三个输入仅改名为 `FitInput`、`SimulationInput`、`RetimeInput` 并开放继承；三个 API 请求是无新增字段的薄子类。领域中的 102 记录、别名优先级、事件、样本及结果类型保留，避免重复字段与映射。应用服务原有执行副本和请求不变性保护保留。拟合、模拟、重定时数值语句、常数及 CSV 写出未改。
4. `VisibilityRequest` 实现应用层 `BallisticVisibilityInput`。应用服务对 `getSatellites`、`toSatellites`、`toBallisticInputs`、模型与载荷转换的调用位置和顺序与基线一致，没有提前转换导致异常优先级变化。领域计算及窗口应用输入/服务不导入 API 类型；领域也不导入基础设施、Spring 或 Jackson。
5. 正式窗口控制器直接承接健康和搜索 HTTP 处理，保留 `ResponseEntity<StreamingResponseBody>`、UTF-8、`writeJsonTo(writer, true)`、writer flush、成功/错误 JSON 媒体类型、400/500 分类及原反斜杠/引号转义。删除继承没有引入重复路由。拟合等入口仍在原位置判断 `outputDir` 字段存在性，绑定异常与计算异常的边界不变。
6. 测试随所属包迁移；直接算法对照适配器仅位于 `src/test`，不再充当产品兼容控制器。冻结原版 ClassLoader 中的旧 FQN 字符串仍保留，继续读取独立旧版参考。新的测试适配器没有取代已提交黄金及重构前独立构建产物。

分层断言范围明确为本轮领域计算与窗口应用输入/服务。既有 `BallisticFileService` 对 API Preview 类型的依赖以及既有空间应用反向依赖未在本轮重构；本报告不宣称整个工程所有 application 类已消除 API 类型依赖。
