## 实际产品变更与独立边界

- `deploy/build.ps1` 按 backend/frontend/all 分别执行 Java8 Maven 验证和冻结 pnpm 安装、完整测试、类型/生产构建；后端不运行前端构建，并拒绝历史生成 static 混入 API 包。
- `deploy/package.ps1` 交付 JAR、独立 frontend、外置 Orekit、外置最小配置和启动脚本，输出 SHA-256 manifest；拒绝覆盖已有目录。`deploy/start-backend.ps1` 从包自身定位资源，可在任意 cwd 启动，将数据库/上传/结果/临时/metadata/日志放在指定绝对运行根，强制 Java8/headless。
- `deploy/application-deploy.yml` 和 `deploy/nginx.conf` 分别提供 Spring 外置配置与保留 `/api/` 路径、multipart、流式下载的反向代理模板。默认 MySQL 环境变量和 JAR 内 Flyway migration 沿用现有配置；demo/H2 仅作隔离验收。Nginx 模板需部署方按安装目录和 `mime.types` 调整路径并运行 `nginx -t`。
- `ApiCorsConfiguration` 默认空来源，不开启跨域；明确配置逗号分隔 Origin 时，仅开放 `/api/**` 和既有 GET/POST/PUT/DELETE/OPTIONS，公开 `Content-Disposition` 供下载客户端读取。正式页面仍使用同源 `/api`，优先由反向代理接入。
- 旧 `SpaceVisibilityControllerIntegrationTest` 的静态能力覆盖保留为 test/resources 中的独立夹具，新增正文标记断言；正式 API JAR 不带 Vue 产物或测试夹具。新增两项真实 MVC CORS 预检/来源隔离测试。无计算 API、数学主体、数值常数、积分节点、采样、CSV 或锁修改；T27 最后批取消修复保留。

独立包结构为 `backend/server.jar`、`frontend/`、`orekit-data/`、`config/application-deploy.yml`、启动脚本和配置说明。运行根结构为 `database/`、`files/uploads`、`files/results`、`files/temp`、`files/metadata`、`logs/`。交付和运行数据不要求源码 cwd，后端不依赖 Swing、桌面选择器或两个原目录。

4. 新构建脚本首次把正常 `java -version` 的 stderr 当作 NativeCommandError，见 [原失败](build-script-before-java-version-fix.txt)。构建/启动脚本改用标准 Process 读取版本，再在另一个新源码副本实际完整执行 all，退出 0，见 [全脚本输出](build-script-all.txt)。
5. 跨域验收初脚本误假设给原弹道 `/orbit/visibility/search` 空 `{}` 应返回 400；实际保留的原默认行为尝试读取默认 CSV 并返回 500，见 [诊断及原CLI指纹](cors-test-contract-negative.json)，原证据在 ignored runtime 的 `cors-before-test-contract-fix-cli.txt` / `cors-diagnostic-cli.txt`。未据此改原计算接口；改用正式目标筛选 JSON 请求验证预检和可读响应后通过。这是验收脚本合同假设错误，不包装成产品故障修复。
