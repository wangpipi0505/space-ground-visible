## 初审 P2：保留原接口允许的 null 任务名（最终已关闭）

位置：`frontend/src/utils/ballisticFit.ts:33`；相关类型 `frontend/src/api/ballisticFitTypes.ts` 的 `BallisticFitRequest.taskName`。

触发：导入原合法完整 FitRequest，仅把 `taskName` 改为 `null`。前端在 HTTP 前抛出“taskName须为字符串”，用户不能执行原拟合。相同任务缺省、空串或空白串可以执行，行为不一致。原 Java `TargetTrajectoryFitter.java:131` 为可 null 的 String，`:479` 调用 `blankToDefault(request.taskName, "task")`，`:3091` 明确将 null 回退为 task；正式 Controller 绑定同一 DTO，Service 只复制原字段，没有要求字符串非 null。

影响：Web 拒绝原接口支持的请求变体，与“完整原请求只适配 outputDir，其余任务参数保留原值”的约定不符。应允许并原样保留 `taskName: null`，交原后端处理缺省，补充定向回归；不要由浏览器主动改写成 task。

实际证据：审查者执行 `node verification/runtime/T23/review/input-probe.mjs`，退出 0，`input-probe.json` 记录缺省、空串、空白串、中文任务名均原值通过，而 null 被上述错误拒绝。输入来自冻结原参考 JSON，未发送计算请求或生成新的黄金。
