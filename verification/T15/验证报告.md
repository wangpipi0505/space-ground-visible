# T15 102 包拟合正式 Web 接入验证

日期：2026-10-13。前置 T14 `476baac` / `task/T14`。本项接入正式拟合与健康路由、受管理结果流转；没有提前注册模拟、重定时或建设 T23 正式前端页面。Java 8、Spring Boot 2.7.18、Orekit 12.0 及前端锁文件保持，原目录与冻结源码只读。

## 实现与原合同

- 正式 `api.ballistic.BallisticFitController` 提供 `GET /api/trajectory/health` 和 `POST /api/trajectory/fit/package102`，由唯一 `application.ballistic.BallisticFitService` 编排。主程序不扫描 `com.tx.alg.api`；迁入该包的旧 `TargetTrajectoryFitController` 保留原无参构造、fit/simulate/retime 方法、注解、签名及 `ErrorResponse`，仅供旧 Java 调用。正式控制器不继承它，真实 HTTP 测试确认 simulate/retime 仍为 404。
- 健康返回纯文本 `OK`；拟合成功直接返回原 `FitRunResult`，原 taskName、targetCount、files 及每个 targetId/model/csvPath/pointCount/warnings 保持。没有增加 fileId 或统一 wrapper。IllegalArgumentException 为原 400，其它计算异常为 500，均只含 `error=describeFailure`。
- Web 边界先保留 JSON 字段存在性，再以同一 Jackson 配置绑定原 `FitRequest`；原字段、别名、扁平 102、coordinateInfo/coordinate/coords、targetInfo/target、tack3d/track3d 均由原 DTO 与算法解释。字段绑定失败转为 MVC 消息转换错误，不当成算法内部 500。
- 原拟合数值主体未重写。唯一原拟合器改动是把目录创建之前的请求非空、package102 非空和原 normalizeStep 调用抽成 `validateFitRequest`，旧入口和 Web 编排复用，保证输入与目录同时非法时仍按原次序报错；阈值、错误文本和公式没有复制到应用层。其余分目标硬约束、Hermite、导数估计、端点修正、区间外二体 RK4、起落事件、ECI/ECEF 两种速度口径、0.1m/0.0001m/s/0.01m/s² 单位、CSV 格式均保持。

## 目录、登记与生命周期

未提交 outputDir 的 Web 请求在 `ballistic.files.results` 真实根下创建随机独占 `fit-*` 目录。应用层复制六个顶层请求字段，仅改执行副本的 outputDir，不修改请求对象或观测列表。原直接 Java `new FitRequest()` 默认仍为 `"."`。

显式内、外目录均由原拟合器创建并写入；明确 `"."`、空白和 null 仍按原算法回退当前服务工作目录，绝不误判为省略字段。显式结果位于管理根时自动登记，位于外部时保留原计算成功行为，辅助登记/下载入口拒绝越界。独立子 JVM 在系统临时目录启动真实 HTTP 服务测试这些场景，没有把点目录测试输出写进源码。

成功管理结果自动登记原实际 CSV 文件，不复制、更名或改变 csvPath；浏览器按 T13 register-result 获取同一 ID，下载原字节、预览原文本，serverPath 可继续作为窗口输入。

结果作用域与 TTL 清理共用存储实例锁，计算本身不持锁。作用域仅保护目录下已有登记结果，多个并发作用域各自持有保护；关闭后仅刷新这些结果的最后使用时间。显式祖先目录即使同时覆盖 uploads，无关上传也只由自身输入/下载租约及最后使用时间决定 TTL。缺省目录在 metadata 下有零字节 `.workspace` 所有权标记，只有标记确证的目录才能被整目录回收，重启也能识别未登记的崩溃遗留。显式复用旧独占目录或其子目录会撤销持久标记及活动拥有者的整目录回滚资格，保护调用者新增文件，已登记单文件仍按原 TTL 处理。

失败仅删除本请求仍拥有的独占目录及其中登记；显式目录、调用者旧文件和先前写出的部分结果均保持原语义。结果清理复用 T13 的逐层真实路径检查，拒绝沿符号链接或 Windows Junction 递归删除，不使用 Files.walk 盲递归。所有权撤销失败不会静默成功；删除/元数据失败保留证据并由既有清理重试。

## 失败定位与修复

1. 原正式路由不存在，先保存两个 404 RED，再新增独立正式控制器及应用服务。成功直接返回原 DTO，不涉及流式返回泛型。
2. resultWorkspace 先解析非法目录，会抢在原 package102/步长校验之前抛错。组合输入测试复现后抽取原前置校验为共用方法，保留原错误先后。
3. 扫描所有 fit-* 目录会误删同前缀显式调用者文件。RED 后改为持久所有权标记；再补显式复用旧 owned 目录 RED，撤销其整目录回收资格后通过。没有用前缀替代所有权判断。
4. Windows 临时目录短名与规范长名指向同一实体，测试最初仅用 startsWith 字面断言失败；与已验证 T13 规则一致改为双方 toRealPath 后比较，产品路径没有改写以迎合测试。
5. 独立审查 P2 指出显式祖先输出目录对后代上传误施加结果 TTL 保护与关闭刷新。新增两个回归先保存 2 项预期失败，再只在清理保护和关闭刷新判断中限定 `!record.upload`；10 项生命周期及最终 285 项 package 通过。配置本就禁止 uploads/results/temp/metadata 同根或嵌套，独占目录回滚、持久标记和显式复用边界保持，未修改数值、输入或 CSV/结果结构。原审查报告与探针日志保留作为修复前证据，最终复审交根代理。
