验证日期：2026-10-13。范围仅为 T10；本报告不将 T11 及后续业务拆分、正式 HTTP、载荷改造标为完成。未更新台账完成状态，未提交 Git。

## 实现与兼容边界

- `BallisticOrbitPropagation` 是从原 `OrbitCalculator` 迁出的唯一三模型计算主体：TWO_BODY、J2_SECULAR、J2_NUMERICAL。原 Kepler 迭代、角度归一化、J2 长期角速度、原初始状态与 RK4 累加顺序保留；μ=3.986004418e14、R=6378137、J2=1.08262668e-3。数值 J2 最大步长30秒、末段阈值1e-9秒，正反向均从原根数历元开始。
- `BallisticCartesianPropagation` 是原拟合二体 RK4 的唯一主体，最大步长1秒，TIME_UNIQUE_EPS_SEC=1e-5、末段阈值1e-9、初始和每步中间状态校验及原异常文本保留。拟合器的区间外外推、事件求根单步以及共享加速度节点调用同一抽取实现；原模拟专用动力学不替换。
- `OrbitCalculator.propagate/propagateAtAbsolute` 的有效输入通过 `OrbitPropagationTool.positionAt`，仅查询位置，不新增速度查询。原拟合 private `propagateTwoBody(initial, dt)` 通过公共工具获取状态；自治动力学用零作**相对时间锚点**，直接保留 dt bits，不把 dt 加到大绝对历元再相减。零不代表实际观测 UTC 历元。普通 Java 的 Cartesian 定义仍支持真实绝对历元并采用原 double 相减。
- 新工具输出显式 J2000 / LEGACY_J2000_SECONDS；UTC 日历2000-01-01正午秒不是 Orekit TT 历元。原公有 `referenceEpochSec/utcOffsetSec` 及可变根数在兼容入口保留。旧相对入口由调用方串行维护全局历元，新领域实例不读取这些全局值。Web 请求状态隔离属于后续事项。
- 原二体/长期 J2 只有位置契约；工具新增速度明确为 t+1秒位置减 t-1秒位置、再乘0.5。数值 J2 和拟合二体速度来自原 RK4 状态。`NativePropagation.stateAt` 默认仍依次查询位置、速度；原生 PV 模型覆盖后仅积分一次，空间旧查询顺序由既有测试验证。
- 原非有限时刻/历元输入没有严格有限数检查。旧入口先执行原根数检查，并通过同一个抽取内核的兼容分支保留原 NaN 行为；普通工具有限时间约束不放宽。
- 迁入最小完整原兼容核心：OrbitCalculator、TargetTrajectoryFitter、TrajectoryFileResolver、VisibilityRequest、OrbitVisibilityController。保留 final 类、嵌套类型规范名和原公有声明；未迁入 Swing、地图、独立 Spring 启动器。旧 API 包不在空间主程序组件扫描下，当前仅供直接 Java 业务回归调用。
- 文件辅助边界沿用 POI 5.2.5、MinIO 8.5.12；本次迁入的解析器使用调用方 URI 凭据，没有迁入硬编码存储密码。纯领域传播不引用文件库、Spring、MyBatis或旧兼容类型。
