# T14 正式弹道可见窗口 Web 接入验证

日期：2026-10-13。前置 T13 `00ac1cf` / `task/T13`。仅接入健康与可见窗口搜索，不提前拟合、模拟、重定时、标准载荷或正式前端页面。Java 8、Spring Boot 2.7.18、Orekit 12.0 与前端锁文件未变；两个原目录及冻结源码只读。

## 实现与原合同

- 正式 `api.ballistic.BallisticVisibilityController` 在原 Boot 主程序扫描范围，提供 `GET /api/orbit/health` 与 `POST /api/orbit/visibility/search`。旧 `com.tx.alg.api.OrbitVisibilityController` 保留无参构造、公开方法和原注解，仍不扫描；正式 Controller 继承其薄响应适配并注入正式应用服务，没有重复登记端点。
- 唯一 `application.ballistic.BallisticVisibilityService` 从旧 Controller 原样抽取请求转换、默认 SAT-A/SAT-B 两星、单/多目标选择及原 V2 调用。旧直接 `new OrbitVisibilityController().search(...)` 也调用此服务，只用原文件解析策略。DTO 四个转换方法仅增加 public 可见性和中文职责说明；原字段、默认值、嵌套类型和别名保持。修正“6星”误注释为实际“2星”。
- `OrbitCalculator` 只增加 `BallisticCsvLoader` 与多目标 V2 的加载器重载；原公开重载委托默认原解析器，原唯一算法主体仅将一处文件读取替换为 `loader.load(input.csvPath)`。原校验先后、采样、并行计算按索引回填、严格时长比较及并列首偏移、弧段门槛与过滤、原轨迹/坐标/三模型实现均保持。
- 成功仍调用 `result.writeJsonTo(writer, true)` 并输出原层级、九位小数与 UTC 字符串；没有重新用 Jackson 序列化结果，也没有统一 Result DTO。400/500 仍为原 `{"error":"..."}` 对象，沿用原转义。T13 文件辅助错误包装不覆盖本控制器。
- 正式 HTTP 方法必须声明 `ResponseEntity<StreamingResponseBody>`：真实 MVC 对旧 `ResponseEntity<?>` 会把成功 lambda 当普通对象输出 `{}`，而不是异步流。旧 Java 方法签名不改；正式覆盖方法透传成功流，将原错误字符串原字节写入 UTF-8 流，显式设置 `application/json` 保持原 JSON 协议。健康仍为文本 `OK`。

## 文件与时间生命周期

Web 单目标与多目标均经 T13 `BallisticTrajectoryService.parse`：上传 serverPath 的租约覆盖完整解析，远程源使用独占 workspace 与 `resolveScoped`；返回完整内存轨迹后立即关闭租约和远程临时文件，后续计算不再读取源文件。两目标各自携带 `ParsedBallisticCsv.referenceEpochSec`；没有用全局 `referenceEpochSec` 覆盖源历元。输出继续取原输入标识，下载临时路径不进入目标 `csvPath`。原单目标结果中的空 `csvPath` 也按原合同保持。

沿用原 HTTP `utcOffsetSec=0` 赋值；UTC 分列解析口径未改。若进程内其它旧 Java 调用并发主动修改该静态字段，仍有原全局可变状态风险，留待 T26；本项不宣称已完成全部并发隔离。原本地路径两侧空白继续可用。非法空位置在窗口边界保留原含句号错误文案，不让文件辅助入口的不同文案改变旧窗口接口。

## 失败诊断与修复记录

1. RED路由两项404，接入唯一服务与正式Controller后健康通过；初轮计算`ResponseEntity<?>`被MVC当对象输出`{}`。正式覆盖方法声明流式泛型，旧公开Java签名仍保留，原手写JSON才实际进入异步输出。
2. 远程坏CSV原解析器抛IllegalArgumentException，本应400。测试初写500失败；核验原行为后仅修正测试预期为400，未将原算法错误改成500。
3. 空单目标位置原error文案为“弹道文件位置不能为空。”，T13辅助解析少句号。`red-empty-path.log`先复现不等；窗口加载边界恢复原完整文案，辅助接口不改。
4. 真实Tomcat错误流的媒体类型在未显式设置时为application/octet-stream，TestRestTemplate无法按JsonNode解码。`web-http-green.log`记录该失败；正式流式适配补application/json后400/500真实HTTP均通过。
5. 默认JVM真实HTTP先运行、再用兼容Java重复运行点1，只有3个heightM末位不同，精确十进制最大差`2E-9 m`。详见`http-jit-observation.json`及`red-empty-path.log`：位置均为 `/allResults/1/visibleSatellites/0/payloadResults/0/targets/0/visibleArcs/0/trajectoryPoints/{1,2,9}/heightM`，差依次为`-1E-9`、`2E-9`、`-2E-9`。T13已直接调用原解析器独立复现冷/热JIT差异；本项不更改原算法、格式、参考数据或容差。常规真实HTTP测试明确点0验证全部窗口字段，另以解释执行点1完整严格对照通过；MockMvc六组合在本次默认JVM及完整测试中也全部严格通过。这些证据不等于宣称所有默认JVM冷/热点1请求总能逐末位一致。
6. 冻结副本不提交，常规构建不能强制依赖它。最终测试默认完整运行HTTP、兼容Java、已提交黄金和非空统计，只有显式`ballistic.frozenReference=true`才追加独立冻结断言；开启却缺失副本立即失败，不静默skip，也不把兼容入口伪称原冻结结果。
