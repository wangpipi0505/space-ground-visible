# T13 Web 文件流转与原弹道解析验证

执行日期：2026-10-13。前置 T12：`338ce76`。本项仅接入文件上传、下载、预览、结果登记及应用层解析，不接入 T14 的窗口计算 HTTP 或后续正式前端页面。Java 8、Spring Boot 2.7.18、Orekit 12.0 和前端锁文件未变。

## 实现边界

- 四个正式辅助端点在既有 Spring Boot 主程序扫描范围内。新增 `api.ballistic` 负责 HTTP/DTO，`application.ballistic` 编排预览与原解析，`infrastructure.files` 负责目录配置、字节限额、持久登记和生命周期。没有新增 Boot 入口或桌面 UI。
- 上传为 `POST /api/v1/ballistic/files`，multipart 的 `file` 必填，`purpose` 可选；201 返回 `fileId/originalName/sizeBytes/contentType/serverPath`。UUID 是登记表键，实体另用随机名称保存，不能由输入 ID 拼文件路径。原名只保存安全末段，保留 Unicode，拒绝控制字符。
- `GET /api/v1/ballistic/files/{fileId}/download` 持租约同步传输原字节。下载头含 ASCII `filename` 与 UTF-8 `filename*`，媒体类型按登记返回；实际输出最多为获取租约时校验过的文件长度，防止外部写入者在流期间扩展文件突破限额。
- `GET /api/v1/ballistic/files/{fileId}/preview?page=1&limit=50` 返回原表头、单元格文本、当前页、总数据行数和真实可知的元信息。默认 limit 上限 500，page/limit 非正数或 limit 超限返回 400。CSV 支持引号、逗号、引号内换行和尾部空列；Excel 读取第一工作表。只有完整匹配现有标准 UTC 20 列表头时才声明 UTC、m、m/s、ECI/ECEF、dt 的 ms；一般表头 metadata 为空，不猜测未知单位。
- `POST /api/v1/ballistic/files/register-result` 接收 `csvPath/taskName/targetId`，只登记真实路径位于结果根内的普通文件。同一真实结果路径复用同一 ID；登记信息保存到 metadata JSON，重启后可恢复。显式旧 outputDir 所生成的外部文件仍可由原 Java 调用处理，但本辅助接口拒绝登记到浏览器下载范围。
- 新辅助错误为 `{code,error,requestId?}`。一般参数 400、未知/已清理引用 404、超限 413、未预期服务错误 500。限定 Controller 的 Advice 不覆盖旧接口；额外 multipart resolver 只匹配上传精确路径，处理 Servlet 在选定 Controller 之前产生的 multipart 错误，其它路径继续旧处理链。
- `BallisticTrajectoryService.parse(sourceLocation)` 接收上传 serverPath 或原本地/HTTP/HTTPS/MinIO 位置，原 `OrbitCalculator.parseBallisticCsvWithReference(Path)` 负责 CSV/XLS/XLSX/XLSM 数值解析。结果单独保留原 `sourceLocation` 和 `ParsedBallisticCsv`，禁止未来回显字段被下载临时路径替换。没有修改静态 referenceEpochSec 来掩盖多目标历元问题，也没有更改 UTC 分列的 `applyOffset=false` 行为。
- 新 `TrajectoryFileResolver.resolveScoped(location,tempDirectory,maxBytes)` 保留重定向及后缀，远程文件关闭即删除；下载失败/超限即删除部分实体。原单参数入口与嵌套规范名保留，独立 Java 旧入口仍使用原系统临时目录/deleteOnExit 兼容语义。后续 Web 计算应使用应用层作用域，不能直接把旧长期临时入口当成 Web 生命周期。

## 配置和清理约定

| 属性 | 缺省值/行为 |
| --- | --- |
| `ballistic.files.root` | `storage`，相对于后端进程工作目录；环境变量 `BALLISTIC_STORAGE_ROOT` |
| `uploads/results/temp/metadata` | 空时为 root 下同名目录；支持独立绝对目录与对应 `BALLISTIC_*_DIR` 环境变量 |
| `max-bytes` | 67108864（64 MiB），必须为正数；`BALLISTIC_MAX_FILE_BYTES` |
| `ttl-millis` | 86400000（24 小时）；`BALLISTIC_FILE_TTL_MILLIS` |
| `cleanup-interval-millis` | 60000；`BALLISTIC_CLEANUP_INTERVAL_MILLIS` |
| `preview-max-rows` | 500；`BALLISTIC_PREVIEW_MAX_ROWS` |

四个真实根不能相同或嵌套；规范化并 `toRealPath` 校验，允许 Windows 8.3 短目录名指向相同实体。每次下载、预览、登记重新检查真实文件边界。单进程独占这些登记目录，不实现多节点共享登记锁。

Servlet 单文件与存储实际复制使用同一 `max-bytes`；multipart 请求总量另留 65536 字节边界/头开销。Servlet multipart 临时目录为 `temp/multipart`，容器负责其请求生命周期。远程解析使用独占 `temp/scope-*`，活动目录受保护，关闭立即删除；进程崩溃遗留 scope 及未登记 `upload-*` 超过 TTL 后回收。登记文件在无活动租约且过期时删除实体、注销 ID；多重租约必须全部关闭，最后使用会刷新保留时间。

清理逐层验证真实目录等于当前规范路径才打开子目录，重定向目录仅删除链接自身。不能用 Java 8 的 `Files.walk` 未带 FOLLOW_LINKS 来推断 NTFS Junction 不会被遍历，已以真实 Windows Junction 回归证明。

## 失败诊断与实际修复

1. 初轮 MockMvc 中文断言把 UTF-8 JSON 用默认 ISO 字符集读取，改为读取响应字节/明确UTF-8；真实上传文件名和原字节从未乱码。结果登记初轮误拒绝 Windows 8.3 目录别名，改为真实路径边界后合法路径通过，外部路径仍被拒绝。
2. 首次参考全量输入超过测试专用1MiB限额，测试根明确调整为2MiB，并同步把超限用例改为2MiB+1；生产默认64MiB未放宽。
3. 真实嵌入式 Tomcat 在 Controller 选择前拒绝超限文件，限定Controller的Advice尚不能匹配，因此原全局500处理被触发。加入只匹配新增上传路径的multipart resolver后真实HTTP获得413，旧错误处理链不变。
4. 原解析器冷/热重复调用的派生大地高有bits差异。独立 `ParserWarmupProbe.java` **直接调用两次原OrbitCalculator，不经过新增服务**：默认JVM 8560点有256个高度bits不同，最大差 **1.862645149230957E-9米**；相同probe `-Xint` 为0个差异、最大差0，日志 `parser-default-jvm.log` / `parser-interpreted-jvm.log`。源文件原始位置/速度与时间仍以bits断言，派生结果由原业务黄金独立核验。没有为了此现象修改算法、数据、黄金或容差。
5. 主代理最初启动的JAR被Windows占用，第一次最后重打包失败于rename，尽管252项测试已完成。停服后重打包成功；后续改用runtime复制JAR启动。最终Junction修复后的完整253项+package同轮成功，不以失败重打包冒充完成。
6. 最后审查增加真实NTFS Junction清理测试，`temp-junction-test.log` 确认原 `Files.walk` 清理删除了JUnit独立临时夹具的外部keep.csv，测试失败。改成每层真实路径核验再递归，链接只删除自身；最终253项通过该回归。此诊断只使用JUnit临时夹具，没有对生产或原目录运行破坏性操作。
7. 补齐500分支时通过暂时移走JUnit专属metadata目录制造真实存储失败，初轮被宽泛的NoSuchFileException处理误分类成404。移除该宽泛处理，只在请求源文件缺失处转为404；基础设施IO异常返回500及追踪号，上传失败finally删除未登记实体。未给旧计算接口增加异常包装。
8. 审查实测原resolver接受两侧空白的本地路径，但新增parse先进入acquirePath，Windows在盘符冒号处抛InvalidPathException；其它平台还可能因字面路径不同漏取管理租约。新增2项回归先复现失败，再仅将acquirePath的实际读取位置trim，与原resolver保持一致；不改ParsedTrajectory保存的调用方原sourceLocation。定向11项与完整256项均按实际结果记录，新增租约测试验证TTL活动保护与关闭后删除，解析测试验证全量8560点及独立源历元。此为本项第8条诊断/修复记录，路径缺陷只实施1轮最小产品修复。
