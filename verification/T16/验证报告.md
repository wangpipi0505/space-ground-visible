## 实现和兼容边界

正式 `api.ballistic.BallisticSimulationController` 提供 `POST /api/trajectory/simulate`，由唯一 `application.ballistic.BallisticSimulationService` 编排。主程序未扫描旧 `com.tx.alg.api` 控制器，没有继承或重复注册其三条计算路由。`GET /api/trajectory/health` 仍只由正式拟合控制器注册，返回原纯文本 `OK`；真实 HTTP 确认 `/retime` 仍为 404。

成功直接返回原 `FitRunResult`：taskName、targetCount、files 以及每个 targetId/model/csvPath/pointCount/warnings 保持，没有增加 fileId 或统一包装。计算 `IllegalArgumentException` 为原 400，其它计算异常为原 500，错误体只含原 `error=describeFailure`，包括异常类型前缀。旧 Java 无参构造、simulate/fit/retime 公开入口和原 DTO 字段均保留。

Controller 仅记录原 JSON 是否存在 outputDir 字段，再用项目原 ObjectMapper 绑定原 `SimulationRequest`，保留缺省值、字段名和别名。绑定错误转为原 MVC 消息转换异常；项目既有 `ApiExceptionHandler` 兜底将它返回 500 的 INTERNAL_ERROR 包体。T03 对绑定/消息转换错误并未承诺计算错误的统一状态和包体，本项没有修改全局错误策略。MockMvc 的 JSON null 请求经原 DTO 绑定为 null 后，仍返回原模拟器的 400 error。

应用服务明确复制全部 35 个公开顶层字段，再仅在执行副本中改缺省输出目录；没有使用会遗漏无 getter 字段的 BeanUtils。phaseEvents 列表是原算法只读输入，保留原 null/空表/非空表语义和元素引用，不写回调用方。包含非默认旧动力学字段和事件的真实调用后，序列化后的请求全部字段及事件对象均与调用前一致。直接 Java `new SimulationRequest().outputDir` 仍为 `"."`。

数值主体没有改写。唯一算法入口改动是把 `simulateToCsv` 目录创建前的原三步校验抽成 `validateSimulationRequest`：请求非空 → `normalizeStep(firstPositive(outputPointDurationSec, outputStepSec, 1.0))` → launchTimeUtc 非空。旧 Java 和 Web 应用服务复用该唯一主体，应用服务先校验再创建工作区；返回的原归一化步长由 `simulateToCsv` 使用。之后仍是原 `Paths.get` / `Files.createDirectories`，再解析时间与端点并计算。因此极小正步长、空发射时刻、含 NUL 目录、非法时间与已有普通文件目录等组合的原错误先后保持，阈值、公式和错误文本没有在服务层复制。

起落点转换、UTC 历元、impactTimeUtc 优先于 impactTime、端点约束 Lambert 射击法、二体 RK4、系统估计落点时间、输出末端非整步、完整 ECI/ECEF 位置速度、能量和 dt、isOriginal 标记、警告顺序及文件命名均由原主体执行。phaseEvents 当前只作为预留扩展输入产生原警告，旧 initialSpeedMs/integrationStepSec/boost 等字段不会被误接成新动力学模型。

## 目录和文件流转

省略 Web outputDir 时复用 `BallisticFileStorage.ResultWorkspace`，在配置 results 下分配已有 `fit-*` 独占目录；模拟没有再造存储、所有权或 TTL 实现，也没有调整已有目录前缀。完成后登记原实际 CSV 并 complete，响应仍保留原 csvPath。缺省失败会回滚自身目录与登记，其它既有结果不受影响。

显式内/外目录仍由原模拟器按原路径创建和写入，显式 null、空白及 `"."` 仍回退当前服务工作目录。独立子 JVM 在系统临时目录启动实际 headless Boot 服务验证三种显式值，没有把运行产物写入源码目录。显式管理范围内的结果自动登记；范围外计算仍成功，辅助 register-result 拒绝越界。显式计算失败保留调用者既有文件；登记限额失败清理自身独占结果，保留另一个已登记结果及其可用下载租约。

成功模拟后，测试在调用辅助登记前直接读取持久元数据确认自动 ID，再以 register-result 两次取得同一 ID；download 与实际 CSV 字节相同，preview 的 21 个表头和前三行逐单元格相同。实际 serverPath 随后作为正式窗口接口的 ballisticCsvPath，HTTP 200 且 allResults 有一条偏移结果；该调用验证结果复用流程，不据此宣称物理样例一定存在可见弧段。

窗口复用最初使用默认卫星历元 `2026/07/01 10:00:00`，而原模拟黄金发射是 `2026-06-04 04:00:00.000`，原 J2 数值回推涉及约 27 天，TestRestTemplate 10 秒读取超时。保留失败后仅在测试请求明确配置卫星 epochUtc 为该模拟发射时刻，同一真实窗口 HTTP 调用通过；未调整产品数值模型、积分步长、连接器或客户端超时。

## 失败定位及处理

1. 原正式 simulate 路由不存在，先保存两个真实 404 RED，再增加独立正式 Controller 和唯一应用服务。
2. 首轮健康/无发射时刻测试把 describeFailure 的异常类型前缀遗漏；确认旧 Java 实际结果后修正测试期望，产品错误格式保持原样。
3. 窗口复用 10 秒超时，比较生成轨迹日期和默认卫星历元定位跨 27 天回推工作量；仅给该流转测试明确同日卫星历元，单项及完整定向复跑通过。
4. MockMvc 非数值字段绑定首轮错误假设为 400；日志追到 HttpMessageNotReadableException 被现有 ApiExceptionHandler 的 Exception 处理器映射为 500，按 T03 真实 MVC 合同修正测试状态与包体断言。没有新增全局处理器或吞掉异常。
