# A01 备注清空缺陷修复报告

## 触发与根因

2026-10-14 的 A01 正式 HTTP 实测发现：对已有任务记录执行 `PUT /api/v1/space/visibility/task-results/{id}`，提交 `{"remark":null}` 返回 500；原实测 requestId 为 `c784f5a7-dd35-4c67-9295-2f86e647abd1`。

`VisibilityTaskResultService.updateRemark` 的业务约定允许 null 清除备注，原实现却构造只含 id 和 remark 的实体并调用 `updateById`。MyBatis-Plus 默认忽略 null 字段，导致 SQL 变成 `UPDATE ZG_VISIBILITY_TASK_RESULT WHERE ID_=?`，缺少 SET。真实 H2 报 `JdbcSQLSyntaxErrorException`，既有异常处理在控制器层转成 HTTP 500。未知主键的 null 更新同样会先遇到非法 SQL，无法按既有约定返回空明细/404。

## 最小修改

仅修改 `backend/src/main/java/com/runisys/orbit/spacevisibility/application/VisibilityTaskResultService.java` 的 `updateRemark`：复用现有 `LambdaUpdateWrapper`，以主键条件显式设置备注列，将 null 作为数据库 NULL 写入。保留原 512 字符上限检查、受影响行数为零时返回 null、成功后调用 `findDetail` 返回完整明细的行为。

未修改实体全局 updateStrategy、数据库结构、控制器接口、其他任务更新方法、数值模型、原版目录、Java/Spring Boot/Orekit 版本及前端锁文件。本子任务不提交、不更新台账或标签。
