# T20 标准载荷输入与共享判定

## 实施前设计与计划

已核对 AGENTS、开发规范、接口基线及空间 PayloadProfileRequest/Factory；使用 brainstorming、writing-plans、TDD、java-spring-boot、ponytail，按已授权协议直接实施，完成前不提交或推进下一项。

最小提取为纯领域 StandardPayloads（保存入口有限值、成对窗口、sentinel 归一与现有 PayloadConstraint 构造）及 PayloadConstraintMath（距离、LVLH、相邻 LOS 速率、太阳夹角）。空间 Factory 的数据库数组与 M/KM 历史读取适配保留；旧 parse 缺字段行为、错误先后保留，公共 normalize 仍由 parse 调用。标准新输入与 profile 保存共用严格入口，距离由 API 公里转米且拒绝转换溢出；原 0/-1 只在内部归一，回显保留配置值。

共享数学保持原 R=normalize(observer)、T=normalize(v-R(v·R))、N=R×T，elevation=asin(LOS单位向量·R)、azimuth=atan2(LOS·N,LOS·T) 后归一 [0,360)。距离和窗口闭边界，太阳角严格小于回避角拒绝；首样本或 dt<=0 速率通过，否则 angle(LOS,previousLOS)/实际相邻采样秒。启动角速度从不参与判定。历史每目标/星/偏移独立，新增标准载荷共享同星原位置，速度使用既有 BallisticOrbitPropagation.velocityAt（数值J2原生速度、二体/长期J2既有±1秒差分）。不额外改变旧位置缓存/传播。

物理上下文不合并：空间仍 DE405→TEME、WGS84 圆柱影与本影豁免；弹道仍解析 J2000 太阳、始终回避及原 J2000→ECEF 椭球遮挡。旧中文四类与空 payload fallback 原逻辑不变。新矩形窗口没有圆锥等价映射；摘要真实 SPACE/GROUND，距离/太阳映射原字段，四锥角 NaN→null。visibleSatellites/payloadResults仍严格按原真实可见弧段生成；全空不补不可见卫星/载荷。空结果根摘要真实，未出窗配置身份由辅助preview及原请求保留。POST /api/v1/ballistic/payloads/preview 接受 PayloadDef 单个对象，返回标准原配置与身份，不写入旧计算响应；缺参数/非法值为400。

## 初轮实际记录

RED为新JSON minDistanceKm不被原PayloadDef识别（1 failure/0 error）。初轮25项定向24通过，独立极轴测试预期严格90度失败：7,000,000径向 normalize 采用原乘倒数，其单位分量为0.9999999999999999，asin得到89.99999914622636。按systematic-debugging确认纯测试夹具非二进制精确，改用2^23米径向使预期严格可表示；不改变旧数学或旧黄金容差。根代理明确空配置只走辅助回显，已移除临时空身份记录方案。

第二轮新扫描测试预期3原点、实际6点：原因是原 visibilitySampleStepSec 自动步长上限1秒，原 interpolateBallistic 会补点。测试改为0、2、3秒三个原点并显式步长2秒；LOS依次+Y、+Z、+Y，独立预期速率45、90度/秒。46阈值只接收前两点，0阈值仅首点后被原稳定两点规则过滤；三原模型与点开关均通过。没有更改采样/插值产品逻辑。

真实HTTP首轮两个测试失败均为夹具断言：JSON IntNode与DoubleNode不相等（值相同，调整请求为明确double）；原双星数据实际仅SAT-A有窗（原T19独立HTTP亦证实）。为确定覆盖双星可见层级，第二颗星复制SAT-A轨道并保留SAT-B身份；旧对空跟踪inner角由源码核对为53度。修正后真实HTTP 2项通过，三偏移、双目标、双星每星三载荷及点开关均验收。数据域为新约束正确性/接口测试，不称原版零差。

## 最终实现与协议

标准输入仅在 satellites[].payloads[].payloadType 显式为 SPACE/GROUND（trim及大小写规范化）时启用。旧PayloadDef类型及旧getter/setter全部保留，旧中文四类、卫星空payloads、顶层fallback原路径保持。九个标准数值字段与空间PayloadProfileRequest同名；minDistanceKm、maxDistanceKm、angleRateDegPerSec、sunAvoidHalfAngleDeg无新默认值，缺失/null拒绝。姿态成对null可选，startup null可选。距离有限非负，max=0不限，否则max>min；方位0≤min<max≤360；俯仰SPACE≥-90/GROUND≥-91且min<max≤90；太阳0..180。SPACE rate=0/-1归一Double.MAX_VALUE，GROUND0为零、-1拒绝；startup=-1内部null，0/正值仅元数据。

StandardPayloads.create由空间Factory保存及弹道DTO共同调用；原parse保留数组/米公里/缺字段适配，normalizeAngleRate和normalizeStartupAngleRate迁入同一个公共纯Java主体。PayloadConstraintMath的range、rate、sun及LVLH主体由空间evaluate和弹道标准判定实际复用。空间原照明和统计计算顺序保留。弹道每次目标/偏移扫描独立创建history，以星为索引，共享同星同目标所有载荷相同的LOS前样本，但每载荷独立约束/段状态；每个采样点（含不可见点）更新历史，dt直接使用当前point.tSec减前point.tSec，不假定1秒。旧位置provider仍先取原位置，仅存在标准载荷的平台才查询既有工具速度，没有改变传播模型。

新标准路径使用闭LVLH/距离/速率窗口与严格太阳夹角，旧中文路径原进出滞回继续保留；标准矩形不套圆锥滞回。原两点、0.001秒稳定过滤、累计、best及输出字段顺序保持。根摘要在标准参与时取首个实际解析的载荷配置；这只代表该配置，不能表示所有载荷。逐实际可见载荷输出真实类型/摘要。标准maxDistanceKm→summary.maxDetectRangeKm，sunAvoidHalfAngleDeg→summary.sunExclusionAngleDeg；四锥角全部null。空结果仍无visibleSatellites，不补空弧段或不可见身份。

新增辅助 POST /api/v1/ballistic/payloads/preview 接受单个标准载荷对象，返回payloadId/payloadName/payloadType及九个完整标准字段（12字段）。身份原值保留，类型大写，其余保持输入公里、度、度/秒及0/-1/null；计算中自动生成身份时，前端仍应使用原请求或实际计算身份。辅助接口只校验/回显，不持久化，错误HTTP400为{code:INVALID_ARGUMENT,error:说明}；旧计算接口仍400单error对象，不混入辅助wrapper。HTTP非法JSON也使用辅助400；旧中文配置无需该辅助标准接口。
