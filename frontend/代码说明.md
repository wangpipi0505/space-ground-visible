## 二、顶层页面如何组织

[App.vue](src/App.vue)组织“规划工作台”“任务结果记录”“可视窗口计算”“目标弹道拟合”。拟合页下设“102包轨迹拟合”“模拟弹道”“弹道重定时”。它还把拟合、模拟和重定时产生的文件引用传给窗口页及重定时页。

### 2.1 空间目标规划

空间工作台的主编排位于[useVisibilityWorkbench.js](src/composables/useVisibilityWorkbench.js)，页面按以下组件展开：

1. TaskSatelliteSelectionStep：检索卫星、分页和任务卫星选择。
2. SatellitePayloadPanel、StandardPayloadEditor：载荷类型、十字段约束、读取与保存。
3. StationConstraintStep、SatelliteStationLinkPanel：地面站约束和站星链路。
4. DownlinkPlanningStep、WindowSelectionPanel：下传窗口计算与观测时间段选择。
5. TargetSelectionStep、ObservationConstraintPanel：目标筛选及共同观测条件。
6. VisibilityPlanningStep：提交规划、查看进度和展示计算结果。

### 2.2 任务结果记录

TaskResultRecordsPanel显示结果列表，TaskResultDetailDrawer显示明细；useVisibilityTaskRecords负责查询状态。观测结果中的目标勾选、目标弧段合并及确认保存由VisibilityPlanningStep使用useSelectionConfirm处理。

## 三、弹道业务页面

| 页面/组件 | 职责 |
| --- | --- |
| [BallisticPayloadConfigurationView.vue](src/views/BallisticPayloadConfigurationView.vue) | 可视窗口工作台：卫星根数、标准载荷、目标文件、发射偏移搜索及请求提交 |
| BallisticWindowControls | 窗口扫描条件及计算操作 |
| BallisticWindowResults | 最优偏移、全部偏移及目标/卫星/载荷弧段结果 |
| BallisticTrajectoryView | 窗口内目标轨迹和点明细 |
| [BallisticFitView.vue](src/views/BallisticFitView.vue) | 102包输入与拟合参数，调用拟合并登记输出文件 |
| [BallisticSimulationView.vue](src/views/BallisticSimulationView.vue) | 起落点、发射时间、输出间隔及系统模拟 |
| [BallisticRetimeView.vue](src/views/BallisticRetimeView.vue) | 选择已有弹道文件并使用新发射时间重定时 |
| BallisticFitFileResult、BallisticFitTrajectory | 拟合类结果文件、告警、预览下载与轨迹展示 |

三个拟合页面产生的真实文件引用由App.vue汇总；窗口页使用同一引用选择文件，fileId用于预览下载，serverPath用于计算请求。

## 四、HTTP与数据约定目录

```text
src/api/
├─ client.js、types.js           空间接口基础请求及公共类型
├─ visibilityTasks.js            异步规划创建、状态、结果和取消
├─ visibilityTaskResults.js      任务记录与明细、备注和选择结果
├─ ballisticHttp.js              弹道计算/文件辅助接口根及错误处理
├─ ballisticFiles.js             上传、结果登记、预览、下载和文件引用
├─ ballisticPayloads.js          标准载荷配置校验回显
├─ ballisticWindow.js            可见窗口HTTP调用
├─ ballisticWindowTypes.js       窗口表单、请求、结果类型
├─ ballisticFit.js               102拟合HTTP调用
├─ ballisticFitTypes.js          102包、拟合参数及文件结果类型
├─ ballisticSimulation.js        系统模拟HTTP调用
└─ ballisticRetime.js            弹道重定时HTTP调用
```

空间默认接口根为/api/v1/space，弹道文件辅助根为/api/v1/ballistic，弹道计算根为/api。环境变量含义与配置方式见[前端载荷配置说明](../docs/前端载荷配置说明.md)。

## 五、表单规则与公共逻辑

| 文件 | 主要内容 |
| --- | --- |
| utils/standardPayload.js | 空间与弹道共同使用的载荷字段、默认值和输入校验 |
| utils/ballisticWindow.js | 窗口请求组装、根数/UTC/偏移条件与文件来源校验 |
| utils/ballisticSwingDefaults.js | 弹道表单采用的默认时间、卫星根数和扫描条件 |
| utils/ballisticFit.js | 102输入解析及拟合请求组装 |
| utils/ballisticSimulation.js | 系统模拟表单与请求组装 |
| utils/winToolSummary.js | 空间规划结果摘要转换 |

典型数据流为“页面表单 → utils校验/组装 → api调用 → 后端响应 → 结果组件”。查某个参数时，可从页面字段追到对应请求类型，再对照接口文档核对单位、默认值和特殊值。

构建及启动命令见[源码包说明](../源码包说明.md)。

## 六、Vue 2 兼容边界

页面继续使用Vue 2.7提供的组合式API与script setup，业务函数、接口字段和原始文件下载规则保持。组件名称在普通script中声明，props和事件改为JavaScript运行时声明；类型说明保留在JSDoc中，types.js只提供数据约定。Vue 2新增字典键使用set/del、数组使用ref以保证页面更新。Element UI使用value/input、visible.sync和具名prop.sync；原生Enter/click通过.native监听。标准数字编辑器按实际输入即时更新业务模型，空值仍为null。

vite.config.js显式将Vue导入统一到同一ESM入口，防止Element UI的CommonJS依赖在生产包中额外加载第二套Vue运行时。此项配置须随构建工程一同集成。

版本、命令和锁文件应一起交付；不要用pnpm 11重新生成本分支锁文件。

完整交付包随附dist和已安装依赖，可直接用Node 14与pnpm 7执行`pnpm build`。依赖以可搬迁的hoisted目录组织，项目源码、页面和锁文件仍与当前分支一致；重新安装及部署步骤见根目录源码包说明。
